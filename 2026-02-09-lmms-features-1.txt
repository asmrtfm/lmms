     Plan: Pattern Track Export/Import Feature

     Context

     Users need to export patterns (groups of instrument tracks with their
     clips) from one LMMS project and import them into another. Currently,
     only individual instrument tracks can be exported as .xpf presets
     (settings only, no clip/note data). A pattern track references a
     collection of instrument tracks in the PatternStore, each with clips at
      a specific bar index. The export must save full instrument track info
     + clip data so that import can reconstruct missing instruments and
     their piano roll data exactly.

     Approach

     Add "Export pattern..." and "Import pattern..." actions to the
     PatternTrack context menu (gear icon). Export saves a .xppt file
     containing all PatternStore tracks with their full settings and clips
     at the specific pattern index. Import reads the file, creates any
     missing instrument tracks, and restores clip data at the target pattern
      index.

     File Changes

     1. include/DataFile.h — Add new DataFile type

     Add PatternData to the Type enum after MidiClip:
     PatternData

     2. src/core/DataFile.cpp — Register new type

     - Add to s_types array: TypeDescStruct{ DataFile::Type::PatternData, 
     "patterndata" }
     - Add .xppt extension validation in validate() method
     - Add .xppt extension in nameWithExtension() method
     - Add Type::PatternData to the write() clean-meta check alongside other
      types

     3. include/TrackOperationsWidget.h — Add new slots

     Add two private slots:
     void exportPattern();
     void importPattern();

     4. src/gui/tracks/TrackOperationsWidget.cpp — Core implementation

     Menu integration (in updateMenu()):
     Add a check for PatternTrackView* similar to the existing
     InstrumentTrackView* and AutomationTrackView* checks:
     if (dynamic_cast<PatternTrackView*>(m_trackView))
     {
         toMenu->addSeparator();
         toMenu->addAction(tr("Export pattern..."), this,
     SLOT(exportPattern()));
         toMenu->addAction(tr("Import pattern..."), this,
     SLOT(importPattern()));
     }

     Export implementation (exportPattern()):
     1. Get PatternTrack* from m_trackView->getTrack() via dynamic_cast
     2. Get the pattern index via patternTrack->patternIndex()
     3. Open a FileDialog in save mode with filter "LMMS pattern file 
     (*.xppt)"
     4. Create DataFile(DataFile::Type::PatternData)
     5. For each track in Engine::patternStore()->tracks():
     a. Call track->saveState(dataFile, content) — this saves full track
     settings + ALL clips
     b. Post-process the XML: remove all clip child elements except the one
     at the target pattern index, and adjust its position to bar 0 so it's
     portable
     6. Write the file via dataFile.writeFile(filename)

     Import implementation (importPattern()):
     1. Get PatternTrack* and target pattern index
     2. Open a FileDialog in open mode with filter "LMMS pattern file 
     (*.xppt)"
     3. Load DataFile from the selected file
     4. Request audio engine change:
     Engine::audioEngine()->requestChangeInModel()
     5. Iterate each <track> element in the file's content:
     a. Extract the track name and instrument name (from <instrument 
     name="..."> child)
     b. Search existing PatternStore tracks for a match (same track name AND
      instrument name)
     c. If match found: use Clip::copyStateTo-like approach — save clip
     state from file XML, restore into the matching track's clip at target
     pattern index, preserving position
     d. If no match: Create new InstrumentTrack in PatternStore via
     Track::create(Track::Type::Instrument, Engine::patternStore()), load
     its settings via track->loadTrackSpecificSettings() from the file
     element, then import the clip
     6. Call Engine::audioEngine()->doneChangeInModel()
     7. Update PatternStore UI

     Additional includes needed in TrackOperationsWidget.cpp:
     - PatternTrackView.h
     - PatternTrack.h
     - PatternStore.h
     - InstrumentTrack.h
     - FileDialog.h
     - Clip.h

     Export XML Format

     <?xml version="1.0"?>
     <lmms-project version="N" type="patterndata" creator="LMMS" 
     creatorversion="...">
       <head/>
       <patterndata>
         <track type="0" name="Kick" muted="0" solo="0" ...>
           <instrumenttrack vol="100" pan="0" ...>
             <instrument name="kicker">...</instrument>
             <eldata .../>
             <fxchain .../>
           </instrumenttrack>
           <midiclip pos="0" len="192" ...>
             <note pos="0" len="48" key="57" vol="100"/>
             ...
           </midiclip>
         </track>
         <track type="0" name="Snare" ...>
           ...
         </track>
       </patterndata>
     </lmms-project>

     Key detail: clips are saved at position 0 (bar 0) regardless of their
     original pattern index, making the file portable. On import, the clip
     content is restored into the destination pattern's clip at the correct
     bar position.

     Import Clip Restoration Strategy

     Following the existing Clip::copyStateTo pattern
     (src/core/Clip.cpp:136):
     1. For each track in the file, find or create the matching PatternStore
      track
     2. Get the destination clip at the target pattern index:
     track->getClip(patternIndex)
     3. Save the destination clip's position
     4. Call clip->restoreState(clipElement) with the clip element from the
     file (which has pos=0)
     5. Restore the original position via clip->movePosition(savedPos)

     For newly created tracks, clips are automatically created at all
     pattern bar positions by Track::create() (which calls
     createClipsForPattern). So we can directly restore state into
     getClip(patternIndex).

     Track Matching Logic (Import)

     Match existing PatternStore tracks by instrument plugin name (from
     <instrument name="...">) AND track name. If both match, reuse the
     track. Otherwise, create a new track. This handles the common case
     where the destination project already has some of the same instruments,
      while still creating any that are missing.

       - Verify clips appear in the new pattern matching the original
     4. Manual test import into empty project:
       - Start a new project
       - Create a PatternTrack
       - Import the .xppt file
       - Verify instrument tracks are created in PatternStore with correct
     instruments/settings
       - Verify clips contain the correct notes
     5. Run existing tests: cd build/tests && ctest --output-on-failure -j2
