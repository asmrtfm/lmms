● The changes look correct. Here's a summary of what was done:

  Changes Made

  src/gui/editors/PianoRoll.cpp — updatePosition()

  Problem: The piano roll's playhead only tracked PlayPos[MidiClip], which is
  only updated when you hit play from the piano roll itself. When playing a
  pattern track from the Pattern Editor, the position lives in PlayPos[Pattern]
  — so the piano roll's playhead sat idle.

  Fix: When the song is playing in Pattern mode, and the currently-open MidiClip
   belongs to the active pattern (i.e., it's in the PatternStore and its clip
  index matches PatternStore::currentPattern()), the piano roll reads the play
  position from PlayPos[Pattern] instead. This makes the playhead move in real
  time, with auto-scroll working too.

  Also removed a long-standing // TODO comment (lines 295-299) that was a dead
  code attempt at exactly this feature.

  src/gui/editors/PositionLine.cpp — paintEvent()

  Added PlayMode::Pattern to the gradient tail condition, so the playhead line
  renders with the proper trailing gradient during pattern playback (it
  previously only rendered for Song and MidiClip modes).

  How it works

  1. updatePosition() is called 60fps by the TimeLineWidget timer
  2. It checks: is the song playing in Pattern mode? Does the open MidiClip
  belong to the currently-playing pattern?
  3. If yes, it reads the tick position from Song::getPlayPos(PlayMode::Pattern)
   instead of the MidiClip playpos
  4. The rest of the logic (pixel calculation, auto-scroll, show/hide) proceeds
  unchanged with this substituted tick value
