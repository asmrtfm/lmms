# Music Production Pipeline Implementation

## User Request
Implement the full LMMS Music Production Pipeline with Ollama + Rubot integration (6 phases).

## What Was Done

### Phase 1: Music Consultation in Rubot
- **constants.py**: Added `MusicModel` enum (6 models), `MusicConsultMode` enum (6 modes), `MUSIC_MODEL_ROUTING` dict, `MUSIC_SYSTEM_PROMPTS` dict, `MUSIC_CONSULT_TIMEOUT_SECONDS`, `CRON_COMMENT_PREFIX`, `SCHEDULE_PRESETS`
- **config.py**: Added `music_model: str = ""` field for global model override
- **generation/music.py**: Created with `resolve_music_model()` (priority: override > config > routing map) and `consult_music_model()` (async httpx call to Ollama /api/chat)
- **mcp/server.py**: Added `music_consult` tool with mode validation, optional RAG context, error handling
- **cli.py**: Added `music` command with `--mode`, `--model`, `--no-knowledge` options

### Phase 2: LMMS Knowledge Ingestion
- **export_knowledge.py**: Exports 43 markdown docs (20 instruments, 21 effects, track subsystems, MIDI reference) from lmms_defaults.py
- **cli.py**: Added `lmms-ingest` command with `--all`, `--defaults`, `--history` flags

### Phase 3: Claude Code Skills
- **~/.claude/skills/music-consult/SKILL.md**: Routes to music_consult MCP tool
- **~/.claude/skills/lmms-produce/SKILL.md**: Multi-step beat production workflow
- **~/.claude/skills/music-ingest/SKILL.md**: Wraps lmms-ingest command

### Phase 4: Scheduling
- **cli.py**: Added `schedule` command group (add/list/remove) managing crontab entries

### Phase 5: Music Knowledge Enrichment
- **knowledge/music_enrichment.py**: Post-processes music chunks through Ollama to generate "recipe" summaries
- Hooked into build-knowledge pipeline in both CLI and MCP server

### Verification
- All CLI commands verified (`rubot music --help`, `rubot lmms-ingest --help`, `rubot schedule --help`)
- Constants, config, model resolution all verified via imports
- MCP server verified: 9 tools including `music_consult`
- Knowledge export tested: 43 docs generated
- Ingestion started: 43 docs being processed (embedding + entity extraction)
- Fixed httpx timeout handling (explicit Timeout object for read vs connect)

### User Requirement: Configurable Models
All model references flow through `resolve_music_model()` with priority chain:
explicit override > config.music_model > MUSIC_MODEL_ROUTING map default.
Config is settable via RUBOT_MUSIC_MODEL env var or TOML config file.
